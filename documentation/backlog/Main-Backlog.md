## Backlog Ordering Rationale

The product backlog is ordered based on a combination of sponsor-approved requirements, technical dependencies, implementation priorities, risk reduction, and design readiness.

Foundational requirements and design activities are prioritized first in Milestone 1 (due September 30, 2026) because they establish the approved scope and provide the structure needed before significant development can begin. This includes confirming the sponsor requirements baseline, defining the information architecture and user journeys, creating initial responsive wireframes, establishing development and repository issue workflows, and defining the frontend integration boundary and Mock API schema.

The primary audience journeys are prioritized next in Milestone 2 — Interactive Sandbox Prototype (due October 28, 2026) because they represent the core functionality of the redesigned website. The "I Need Help" path must support workshop discovery, ZIP-code search, workshop information, and registration, while the "I Want to Help" path must provide separate Donate, Volunteer, and Advocate experiences. Responsive design, targeted WCAG 2.1 Level AA accessibility remediation, and Mock API/sandbox integration are prioritized alongside these core user journeys to ensure a functional, independently testable web prototype.

Final production readiness, approved integration boundaries, performance and technical SEO optimization, and administrative capabilities are addressed in Milestone 3 — Production Release & Handover (due December 4, 2026). This milestone builds on the validated frontend prototype by refining applicable public forms and integration behavior while preserving established external workflows such as Gravity Forms/Salesforce and Stripe. It also addresses final performance and SEO optimization, verification activities, and the lightweight website administration interface within the approved project scope.

### **Estimation Approach**
Story points were assigned using relative estimation rather than time-based estimation. The team considered factors such as technical complexity, required effort, uncertainty, dependencies, integration risk, and testing requirements.

Each Product Backlog Item (PBI) was compared against the other items to determine whether it was smaller, similar in size, or larger in scope. Higher story points reflect greater implementation complexity, dependencies, or uncertainty, while lower story points represent work that is more narrowly scoped or better understood.

Estimation was performed sequentially from the top of the backlog to the bottom to maintain consistent relative comparison across the Product Backlog.

The items are distributed across three strategic project milestones:
- **Milestone 1 — Requirements & Design (Due September 30, 2026):** PBIs 1–5 (27 pts total) focus on establishing baseline requirements, user journey maps, wireframes, frontend integration boundaries/Mock API contracts, and repository development infrastructure.

- **Milestone 2 — Interactive Sandbox Prototype (Due October 28, 2026):** PBIs 6–12 (47 pts total) focus on the core dual-path navigation and audience journeys, workshop discovery and registration, responsive frontend behavior, targeted Phase 1 accessibility remediation, and Mock API/sandbox integration with documented production integration boundaries.

- **Milestone 3 — Production Release & Handover (Due December 4, 2026):** PBIs 13–15 (21 pts total) focus on applicable public forms and approved production integration boundaries, performance and technical SEO optimization, and lightweight website administration capabilities.
